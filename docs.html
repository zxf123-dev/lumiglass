01概述

Lumi Glass 是一套以 Apple「液态玻璃」材质为核心的界面组件库。它不依赖任何框架，全部由 HTML + CSS 组成，唯一的可选脚本是 glass.js（约 4KB），负责折射滤镜注入、指针光斑与主题切换。

文件结构

├─ glass-core.css      通用层：Token、玻璃基类、按钮、表单、控件、反馈、
│                      时间线 / 步骤条 / 上传区 / 命令面板 / 日期选择
├─ glass-mobile.css    手机端：手机壳、导航、列表、Tab Bar、抽屉、控制中心、

适合什么

  • 产品官网、后台仪表盘、作品集、活动页中的导航、工具条、卡片悬浮层
  • 移动端 H5 / 小程序 WebView 中的悬浮控制层
  • 需要「有厚度的半透明材质」但不想引入 UI 框架的项目

不适合什么

! 不要把玻璃用在长文内容卡上。文字密集的内容区需要近乎不透明的底，否则文字会随背景滚动失去对比度——这是 HIG 的硬规则，不是风格偏好。

同样不建议：全屏铺满玻璃（性能开销大且没有层次）、深浅文字直接叠在强彩色背景上、把玻璃套三层以上。

02快速开始

把 glass/ 目录整个拷进项目，然后三步接入。想先看一个真实页面长什么样，打开 starter.html——它只有背景层、顶栏和几块内容，是可以直接改的业务骨架。接入是否成功可打开 docs-test.html（仅引文档中的 CSS/JS，自动跑冒烟测试）。

第 1 步：引样式

<!-- 通用层必引；按平台选一个 -->
<link rel="stylesheet" href="glass/glass-core.css">
<link rel="stylesheet" href="glass/glass-web.css">   <!-- 或 glass-mobile.css -->

<!-- 可选：整页模板组件（后台图表 / 官网 Hero / 商品卡 / 认证页） -->
<link rel="stylesheet" href="glass/glass-templates.css">

第 2 步：给容器加平台类

<body class="web">      <!-- 桌面密度：按钮 40px、输入 44px -->
<body class="mobile">   <!-- 触控密度：按钮 50px、命中区 44px -->

第 3 步（可选）：引脚本

<script src="glass/glass.js"></script>
<!-- 获得：边缘折射、鼠标光斑、顶栏滚动加厚、明暗切换、Toast -->
<!-- 可选：body data-wallpaper="aurora" 启用动态壁纸（玻璃底下有活内容可折射） -->
<!-- Toast 无需手写容器，glass.js 会自动创建 .toast-zone -->

最小示例

<body class="web">
  <div class="glass" style="padding:20px;border-radius:20px">
    <h3>我的第一块玻璃</h3>
    <p>把它放在有内容的背景上，折射才会出现。</p>
  </div>
</body>

第 4 步（可选）：官网级液态动效

与 landing.html 一致的动态壁纸、WebGL 液态层、顶栏页间过渡，在 glass.js 之后按顺序追加：

<link rel="stylesheet" href="glass/glass-lg.css">
<body class="web" data-wallpaper="aurora">

<script src="glass/glass.js"></script>
<script src="glass/site-topbar.js"></script>
<script src="glass/glass-liquid-engine.js"></script>
<script src="glass/glass-webgl.js"></script>
<!-- 业务页用 app 略减面板光效；若要关控件 WebGL：data-lg-controls="off" -->

完整自检见 docs-test.html：收录 §06 全部 demo、§07 弹簧阻尼抽样、网页/手机布局与 html.lg-on 检测（不含壁纸调音）。

i 玻璃必须有内容可以折射。纯白背景上玻璃会退化成「白框」。要么把组件放在照片 / 彩色渐变上，要么参考案例页用一块「展示台」背景。接入前先确认：这块玻璃底下有什么？

方式 B：npm 安装（推荐工程化项目）

npm install lumiglass
// Vite / Vue CLI / CRA / Next.js 通用 —— 引全局 CSS 一次即可
import 'lumiglass/css/glass-core.css';
import 'lumiglass/css/glass-web.css';    // 或 glass-mobile.css
import 'lumiglass/js/glass.js';          // 可选：折射 / 光斑 / 主题 / Toast

包内文件与 glass/ 目录一一对应（core / web / mobile / templates 四层），package.json 已配好 exports，按子路径直接引。发布步骤见项目根目录 lumiglass/PUBLISH.md。

在 Vue / React 中使用

本库是纯 CSS 类名库，不依赖任何框架——类名写在 class（Vue）或 className（React）里即可，行为层（Toast / 主题 / 折射）由全局 LiquidGlass 对象提供。

<!-- Vue 3 单文件组件 -->
<template>
  <button class="btn primary" @click="save">保存</button>
</template>
<script setup>
function save() { LiquidGlass.toast('已保存'); }
</script>
/* React 组件 */
export function SaveButton() {
  return <button className="btn primary"
    onClick={() => LiquidGlass.toast('已保存')}>保存</button>;
}
场景做法
路由切换（Vue Router / React Router）新页面挂载后调一次 LiquidGlass.refresh()，重新绑定吸顶加厚与折射检测
明暗主题按钮加 data-theme-toggle 属性即可；或在代码里调 LiquidGlass.setTheme('dark')
Toast直接调 LiquidGlass.toast('文案')；案例页的 data-toast 属性绑定只是演示代码，业务里不要依赖
SSR（Next.js / Nuxt）CSS 在服务端正常引入；glass.js 操作 DOM，只在客户端引入（useEffect / onMounted 里 import，或加 <Script> 标记）
作用域冲突类名无前缀，可用 PostCSS 包装 .lgk .btn 一次性加命名空间（见第 14 章）

图标方案

库本身不内置图标字体，保持零依赖；演示里的 ⌕ ✕ ＋ 是字符兜底。上线项目建议接入一套 SVG 线性图标（如 lucide、tabler-icons），笔画粗细 1.5–1.8 最配玻璃质感——主题切换按钮的太阳 / 月亮就是 glass.js 按这个规格自动注入的 SVG，可直接对照。

03设计原理

三层配方

每一块玻璃由三层叠加而成，三者缺一不可：

层实现作用
① 磨砂backdrop-filter: blur() saturate()让底下的内容模糊并提饱和，玻璃「吃掉」背景色
② 折射（可选）filter: url(#lg-lens) + JS 抓取层backdrop-filter: url() 只有极少数引擎支持，所以折射由 glass.js 把壁纸抓进小 canvas、对最外一圈施加位移滤镜（body[data-lens="on"] 启用；Chromium 上主流液态玻璃站同样只用磨砂）
③ 边缘与镜面padding-box/border-box 双层背景 + inset 高光 + 投影边框是一圈「角亮中暗」的对角光带（光从左上穿入、右下穿出）；顶部高光模拟镜面、外投影表达厚度

五种材质

HIG 定义了 regular / clear，本库补全为五级阶梯。关键规律：模糊越低，折射越明显——blur 18px 时位移滤镜基本被糊掉，只剩「毛玻璃」；想要一眼液态，用 clear（2px）并保证玻璃下有颜色：

类名模糊 · 身体用在典型场景
.glass.clear2px · 白 10%彩色背景 / 照片之上，透镜感最强官网 Hero、控制层、取景器控件
.glass16px · 白 42%（默认）内容之上的控制层导航、卡片、按钮、输入框
.glass.tinted12px · 主色染 55%品牌色染色玻璃，白字强调面板、选中态容器
.glass.thin10px · 白 16%玻璃内部的嵌套小组件控制中心内的格子
.glass.overlay24px · 白 72%弹层，可读性优先弹窗、Toast、下拉菜单

层级模型

一个页面永远分三层，玻璃只属于第 3 层：

  • 页面背景层：照片、渐变、工程网格——负责给玻璃提供可折射的颜色
  • 内容层：近乎不透明的底（白 85%+），承载正文、表格、长文
  • 控制层：玻璃。导航、工具条、弹窗、悬浮按钮——可以动的那一层

案例页反复强调的「侧栏悬浮 / 内容实体底」对比，就是这三层的具象化。

液态交互（fx）

  • 边框亮环：hover 时 .glass::after 显示 1.2px 对角亮边（不进盒内）；
  • 追光镜面：大面板加 .lg-sheen，glass.js 把指针位置写入 --lg-mx / --lg-my，::before 径向高光跟随；
  • 按压弹簧：按钮 / FAB / Dock 由 JS 阻尼弹簧驱动（按下 ~1.12、松开略过冲再收敛）；无 JS 时降级 CSS :active；
  • 浮起：卡片类自动挂 fx-lift（阴影加深，无位移）。

动态壁纸（body[data-wallpaper]）

静态渐变背景是「玻璃显假」的头号原因——光不动，折射就死板。给 <body> 加 data-wallpaper="lumi" 并引入 glass.js，页面底层会挂一张全屏 canvas：三段同明度底色 + 4 个缓慢漂移的光斑（主周期约 46 秒，半分辨率渲染、30fps 节流，prefers-reduced-motion 自动降为静帧，切换主题自动换色）。

<body data-wallpaper="lumi">
<script src="glass/glass.js"></script>

// JS 切换 / 关闭
LiquidGlass.setWallpaper('sonoma');
LiquidGlass.setWallpaper(null);

内置五套预设：lumi（灰蓝工作区）、aurora（低饱和紫雾，对齐 Glass UI 官网）、sonoma / tahoe / graphite。业务页用 lumi，营销 Hero 用 aurora。

WebGL 液态引擎（glass-liquid-engine.js + glass-webgl.js）

与 Glass UI 相同架构：全屏 WebGL 画布在 UI 下方，data-glass 控件由着色器绘制折射 + 色散 + 追光边缘；CSS 使用 .lg 材质层（glass-lg.css）。

<link rel="stylesheet" href="glass/glass-lg.css">
<body data-wallpaper="aurora" data-lg-engine="on">
<script src="glass/glass.js"></script>
<script src="glass/glass-liquid-engine.js"></script>
<script src="glass/glass-webgl.js"></script>

<div class="lg lg-regular lg-surface" data-glass="card" data-frost="1" data-tint="0.2">…</div>

壁纸 canvas 带 data-glass-backdrop；引擎就绪后 html.lg-ready 会隐藏 DOM 壁纸副本，避免双层。Chrome 另加 #lg-lens 给未走 WebGL 的 .lg 条。

官网示例：landing.html（暗色 + aurora + 控制中心）。

光效三档 data-lg-profile

写在 <body> 上，控制 WebGL 强度与控件是否挂 data-glass。未写时默认为 showcase。

档位典型页面面板 WebGL控件 WebGL引擎倾向
appstarter / admin / shop与 studio 同引擎强度开仅横幅等极少元素不自动挂 WebGL 面板
studio产品站、自控强度中等开（开关旋钮、蓝轨滑块、进度条等）折中参数，可改源码表
showcase（默认）index / docs / white强开高折射、高 rim
 
<body data-lg-profile="studio" data-wallpaper="lumi">

自定义 studio 参数

在 glass/glass-webgl.js 顶部修改对象 LG_PROFILE_STUDIO（折射、色散、frost、bezel、mergeK、rim）。保存后硬刷新；控制台可查看默认值：

// 引擎就绪后
LiquidGlassRuntime.studioDefaults
// 当前档位
LiquidGlassRuntime.profile()

彩虹滑块拇指：全屏 WebGL 在 DOM 彩虹轨下方，无法像蓝轨一样折射渐变轨。彩虹轨使用 thumb-rainbow：CSS 玻璃层 + JS 同步 --rainbow-w / --rainbow-x 采样与轨道相同的 --lg-rainbow-track。蓝轨拇指仍走 WebGL knob。

04设计 Token

所有 Token 以 --lg- 为前缀，定义在 glass-core.css 的 :root。改主题只改这一段。

文本与背景

--lg-ink主文本 #1d1d1f
--lg-ink-2次级文本 #6e6e73
--lg-ink-3辅助文本 #a1a1a6
--lg-line发丝线 / 分隔线 #e8e8ed
--lg-page页面底色 #ffffff

系统色

--lg-blue主操作、选中态
--lg-blue-deep白底上的链接与文字蓝
--lg-green成功、开启
--lg-red破坏性、错误
--lg-orange警告
--lg-yellow收藏、评分星、高亮
--lg-purple辅助强调

玻璃材质

--lg-blur模糊半径，默认 14px。模糊越低折射越明显：clear 材质 3px、tinted 12px、thin 10px
--lg-sat饱和度提升，默认 180%；过高会「荧光」
--lg-wash玻璃基色填充（均匀，亮白 38% / 暗石墨 42%——暗色玻璃有自己的身体，不靠背景透色）
--lg-rim-hi / rim-lo边框光带：对角亮角 80% ↔ 中段暗边 18%，光从左上穿入右下穿出
--lg-highlight顶缘高光线（亮 60% / 暗 16%）
--lg-drop外投影基色（亮 rgba(15,23,42,.14) / 暗 45% 黑）
--lg-sheen镜面高光；暗色下降到 52%
--lg-shadow标准悬浮投影
--lg-shadow-lifthover 上浮时的加深投影

圆角、动效与层级

--lg-radius-lg / … / xs28 / 24 / 18 / 14 / 10 五档
--lg-ease-springcubic-bezier(.34,1.7,.64,1) 弹性回弹
--lg-ease-outcubic-bezier(.22,.61,.36,1) 通用出场
--lg-dur标准时长 350ms
--lg-hit最小命中区 44px，触控组件必须满足
--lg-z-sticky / z-toast / z-dialog层级基准：悬浮层 100 / Toast 300 / 弹窗 400

明暗双主题

暗色通过 [data-theme="dark"] 覆盖同一批 Token 实现：文字反转为 #f5f5f7 / 页面底 #0b0d12，填充降低到 9%→2%，描边降到 15%，镜面高光降到 52%，分隔线转为白 12%。切换方式二选一：

<html data-theme="dark">          <!-- 手动指定 -->

<!-- 或引 glass.js 后用按钮切换（记住用户偏好） -->
<button data-theme-toggle>☾</button>

未设置 data-theme 时自动跟随系统的 prefers-color-scheme。网页端案例页右上角就是活的切换按钮。

08无障碍

已内置

  • 键盘焦点：全局 :focus-visible 2.5px 蓝色外框，只在键盘导航时出现，不干扰鼠标用户
  • 命中区：手机端全部 ≥44px；桌面 ≥32px；滑块旋钮本身就是 44px
  • 减少透明度：系统开启 prefers-reduced-transparency 时，所有玻璃自动退回 #f7f7fa 不透明底
  • 减少动效：prefers-reduced-motion 全量降级
  • 暗色对比：暗色 Token 的文本层级（f5f5f7 / a1a1a6 / 6e6e73）满足 WCAG AA 正文对比

接入方需要补的

  • 图标按钮加 aria-label（案例页都写了）
  • 开关 / 分段保留原生 input，不要改成 div + JS 模拟
  • 弹窗用原生 dialog，获得免费的空间导航与 Esc 关闭
  • Toast 加 role="status"（LiquidGlass.toast 已内置）
  • 彩色背景上的正文，交付前跑一次对比度检查（≥4.5:1）

09性能预算

backdrop-filter 是本库唯一的昂贵属性。经验预算：

设备档同屏玻璃数量上限备注
旗舰手机≤ 12滚动区内的玻璃卡片要控制
中端手机≤ 8相册九宫格这类批量内容绝不套玻璃
桌面≤ 20视口大，重绘区域也大，同样要克制

规则

  • 不嵌套：玻璃里放玻璃会让模糊互相吃色、成本翻倍。唯一例外是控制中心（用 .glass.thin 内嵌）
  • 长列表不套玻璃：列表行用透明 + 发丝线，只有「组」的容器是玻璃
  • 滚动区域：滚动内容从玻璃下方穿过是安全的；但不要让玻璃本身滚动（模糊区域持续变化最贵）
  • 不要加 will-change: backdrop-filter：会强制常驻合成层，得不偿失
  • 折射滤镜只在 Chromium 启用；Safari / Firefox 自动回落到纯磨砂，不额外付出成本

  • 第 2 层：默认规则 → 磨砂 + 描边 + 高光 + 投影
  • 第 3 层：@supports not (backdrop-filter) → 高不透明度纯色底

11定制主题

换品牌色只需要覆盖 Token，不要改组件规则：

/* 你的 theme.css —— 在 glass-core.css 之后引入 */
:root {
  --lg-blue: #7c5cff;        /* 品牌紫 */
  --lg-blue-deep: #5a3ce0;
  --lg-radius: 20px;         /* 更收敛的圆角 */
  --lg-blur: 14px;           /* 更轻的磨砂 */
}
[data-theme="dark"] {
  --lg-blue: #9b85ff;
}

品牌色替换后，按钮、开关、焦点环、进度条、chip、选中态会全部自动跟随——组件规则里引用的都是 Token。

换玻璃「性格」的三个旋钮

  • --lg-blur：越大越「磨砂」，小了会更「透」
  • --lg-fill-1 / 2：控制白度。降到 .4/.1 接近 clear，升到 .8/.6 接近毛玻璃实底
  • --lg-sheen：镜面感强弱。暗色场景 0.5 左右，否则会「发光」

12接入检查清单

发布前逐项过一遍，全部满足才算「液态玻璃正确接入」：

  • 每块玻璃底下都有可折射的内容（照片 / 彩色 / 网格），没有「白框玻璃」
  • 玻璃只出现在控制层；正文与表格区使用近乎不透明的底
  • 同屏玻璃数量在预算内；长列表与相册网格未套玻璃
  • 没有玻璃嵌玻璃（控制中心除外，且内层用 .thin）
  • body 加了 web 或 mobile 类，密度与端匹配
  • 手机端可点元素全部 ≥44px；输入框字号 ≥15px
  • 每个图标按钮有 aria-label；开关/分段保留原生 input

13常见问题

玻璃显示成灰块 / 白块

按顺序检查：① 祖先有没有 filter、isolation:isolate、contain（会截断 backdrop 采样链）；② 玻璃底下是不是纯白背景（没有可折射内容）；③ 是否嵌套了玻璃（互相吃色）。90% 的问题出在第一条。

hover 没有任何反应

检查是否有人写了「hover 加白」——浅色底上叠白等于零反馈。本库的 hover 是中性加深 + 上浮 2px + 光斑；如果你自定义了 hover，请遵循同一方向。

Safari 上边缘没有折射

预期行为。折射滤镜（feDisplacementMap）只有 Chromium 支持，Safari / Firefox 自动回落到纯磨砂。不要为补齐折射而引入图片模拟，降级本身就是分层体验。

滚动时玻璃区域闪烁

通常是玻璃元素本身在滚动（模糊区域持续重绘）。让玻璃固定、让内容从它下方穿过；或减少同屏玻璃数量。

暗色模式下组件发「发光塑料」感

把 --lg-sheen 降到 0.5 以下、检查是否忘了引暗色 Token（只有 [data-theme="dark"] 覆盖段生效才会出现半亮半暗）。

能用在 React / Vue 项目里吗

可以，只是 CSS。把 glass/ 放进静态资源，或在入口文件 import 两个 CSS；glass.js 在 useEffect / onMounted 里加载一次即可。注意组件类名不要与框架 UI 库重名冲突（前缀 lg- 的工具类除外）。

如何只取一部分组件

core 里的组件块互相独立（每个区块顶部有注释分隔线），整块剪切即可；但 :root Token 段与 .glass 基类是所有组件的前置依赖，必须保留。
